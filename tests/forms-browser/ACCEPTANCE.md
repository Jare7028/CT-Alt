# Desktop Forms synthetic acceptance

This suite uses original synthetic company, Auth-user and form data only. It exercises the actual desktop component and its attached React handlers against mocked API responses; it does not prove hosted schema, real Auth or a production release.

The isolated browser window was `127.0.0.1:5196`, granted by the integrator. All 68 persistent cases passed in 2.3 minutes on 4 October 2026, using the installed Chromium and the actual client component. Targeted ESLint and a no-emit TypeScript check of the owned client/browser files passed. The integrator owns full checks/build, signed acceptance, shared CI hooks and release; these synthetic results do not claim real server persistence, current hosted permission acceptance or cross-device autosave.

Coverage includes separate management and assigned respondent authority (including an unassigned owner), ordered builder fields/stable option IDs and frozen published schemas, literal title search, a searched 1,006-person roster and retained selections across pages/search, and the 500-selection bound checked through an actual disabled checkbox's attached React handler. Management snapshots reject private in-progress responses.

Autosave is debounced by 650 milliseconds and serialized. Tests retain later in-memory edits during a held save, use its acknowledged response revision for a new UUID, flush progress before one submission, accept explicit No and incomplete numeric progress, reject invalid submitted decimal grammar, resume after a corrected draft and enforce the aggregate 64 KiB answer bound before any outbound save. Only durable acknowledgments show “Progress saved”; unsent answers disappear on departure and are never stored in the recovery marker.

Submission tests cover respondent/admin editing, explicit local discard, retained prior content with inherited frozen schema, explicit review, separate answer-editor/review timestamps, archived read-only detail and complete 23-row history through bounded ten-row pages. Conflict refresh preserves local respondent or admin answers while obtaining the current exact resource revisions.

Privacy/recovery tests cover current 401/403, foreign/malformed DTOs, wrong actor/revision or missing acknowledgments, definitive absence versus recorded recovery, recovery denial, held POST before headers, held decoded acknowledgment and actual attached React refresh/save/view handlers, actor/company/role/departure invalidation, late detail/history responses and a prior roster read invalidated when a mutation begins. Recovery session state contains exactly action and operation UUID; it cannot restore discarded answer bytes. No automatic payload retry, unload beacon or browser answer persistence is used.

Agent-browser smoke passed: meaningful shell/content, Forms controls/link present and no framework error overlay. Its own session was closed. A separate temporary capture test passed (3.3 seconds), and original synthetic 1440×1050 reader/builder/submission screenshots plus a full reader capture were inspected under `/tmp/ct-alt-forms-*.png`. They contain test switches and a development badge, so they are not committed as production visual evidence. The capture test and temporary fixture route were removed. Verified owned dev parent/children were stopped, port 5196 was confirmed closed and the owned `.next/dev` cache was removed before handing the worktree back.

This first delivery does not include dynamic audiences, published schema editing, multiple submissions, exports/summaries, conditional fields/formulas, file/signature/location fields, schedules/notifications or mobile polish. Those remain explicit roadmap increments.

A bounded follow-up added nine regressions for concurrent submission with retained local progress and for malformed acknowledgment target/status. The UI now offers an explicit guarded Discard unsaved answers action; unknown/held writes and revoked access cannot use it. Administrator/review receipts bind the exact response ID, personal receipts retain a known original response ID, and response status matches the acknowledged action. Three further numeric/text parity regressions cover: cleared optional/required numbers omit the answer key through the actual attached handler, and whitespace-only required text retains exact partial progress but blocks submission. No server validation was relaxed. The final combined 68-case rerun passed on immutable UI source `1e70f8cca4ae4f1e60eb1213ad5c229397f1db14`. Its granted dev/browser window was cleaned again before handoff, with port 5196 closed and the temporary route/cache removed.
