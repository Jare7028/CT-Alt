# Desktop conversation message search

This slice adds a separate search-results view to existing CT Alt Chat. Public [Chat for Users](https://help.connecteam.com/en/articles/6712594-chat-for-users), [Starting Guide to the Chat](https://help.connecteam.com/en/articles/5839181-starting-guide-to-the-chat), and [Is the Chat Secure?](https://help.connecteam.com/en/articles/8222059-is-the-chat-secure) informed conversation navigation and privacy. Public Help Center searches did not establish a current dedicated message-search specification. This is the authorized conversation-scoped literal-text baseline, not a complete visual or functional parity claim.

## Supported desktop behavior

The existing conversation-name filter remains separate. Within a selected conversation, Search this conversation accepts up to100 characters. Search messages/Enter submits the trimmed literal query to the signed search API. Search consumes its raw `ChatSearchData` response; ordinary Chat actions retain their separate `{data}` envelope. Synthetic search responses use the same raw DTO, checked against the exported type. The explicit results region shows exact total, newest-first messages, sender and full date/time. Message bodies are rendered as text, including percent/underscore, brackets and HTML-like content. No result body is treated as HTML or a regular expression. Load older results sends the API's exact opaque cursor with the same query and conversation; decimal sequence strings remain distinct above2^53 and are checked in descending bigint order without conversion to Number. Results never enter the legacy normal-history merge helper.

Clear search or an empty query restores normal history and retains the current unsent draft. Changing an existing search query aborts/discards its old request and removes prior results until the next explicit search. Conversation selection, company/Auth actor replacement and management/create controls invalidate search. Company+actor keys reset all conversation state, including drafts, even when a parent replaces props on the same Chat component.

A first-page error stays visible as an error with no apparent empty success. An older-page transport/read error retains the already-visible authorized page and offers the same cursor retry. Only a successful zero-count response shows No matching messages. Malformed/wrong-scope data and numeric sequences are errors.401/403 clears selected conversation, history, results, composer, group/directory state and conversation cache; this also applies when an auth-denial body is missing/malformed. Current list polls remain active during search to observe access changes. Normal history and read marking pause during search, including failed-search and changed-query states; an already-in-flight history success cannot advance a read marker. A current conversation's in-flight history denial still clears search despite the polling effect transition. Posting denial aborts search, fences older lists and retains readable normal history with its composer restriction.

## Synthetic acceptance

Run `CT_ALT_AGENT_BROWSER=/path/to/agent-browser node scripts/test-chat-browser.mjs` in the CT Alt checkout with exclusive port5193 and `.next` access. The temporary client fixture is generated/removed by the runner and never committed as an app route. Supabase configuration is deliberately invalid and Playwright intercepts all Chat requests; no account, database, hosted project, workforce data or credential is used. Synthetic scope controls intentionally replace actor/company props without remounting the fixture, exercising the stricter internal Chat key. The production server page retains its company key and verified-auth actor props.

The runner retains all13 existing posting, idempotent lost-response retry, history reconnect, revocation, group/directory and stale-response regressions.16 search cases cover literal/bigint pagination, opaque retry, genuine empty success, first/older failures, wrong-scope/malformed responses, query/conversation/actor/company changes, search/poll/post denial, malformed auth denial, normal-history in-flight success/denial and read-marker suppression. The desktop screenshot `test-results/chat-search-desktop.png` is our synthetic1440×1050 rendered view; it shows the search toolbar, separate results with sender/date, retained composer draft and full company shell. It is ignored local acceptance evidence, not a competitor capture. Agent-browser verifies content, controls, no framework error overlay and home navigation before Playwright.

The final component run against the actual raw search DTO passed all29 cases (16 search plus13 retained Chat cases). Repository check and production build passed with the integrated API. Fresh signed Auth acceptance and release evidence belong to the integration owner. These component checks complement the signed API/SQL tests in [chat-search-acceptance.md](chat-search-acceptance.md); fresh real Auth/browser acceptance remains required before release. Hosted migrations and credentials were untouched by this UI work.

## Remaining scope

Global/all-conversation search, sender/date/media filters, highlighting, jumping from a result into historical context, attachments, starred messages, reactions and other Chat parity features remain separate work. This slice prioritizes desktop function; existing mobile containment is preserved without new mobile polish.
