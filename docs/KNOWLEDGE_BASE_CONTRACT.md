# Desktop Knowledge Base delivery contract

Consult [the public reference research](knowledge-base-reference.md) and the public official guides before implementation. Preserve the full workforce roadmap. Original CT Alt code/branding; desktop first, only verified CT Alt free resources, synthetic acceptance. No hosted fixtures, employee notifications or paid services. No application service-role key.

Deliver multiple bases with real section/nested folders, plain text and named external links, in-base moves and persistent sibling order, base-scoped title search, selected Auth-account audiences, reader versus management views, and actual open-event insights. Private files, rich text, dynamic Smart Group assignments, granular administrators and other documented workflows remain explicitly tracked next increments; do not show functional-looking unavailable controls or call this full parity.

Owner/admin management requires current confirmed nonanonymous active company membership. Managers/employees read only published bases to which their current original Auth actor is assigned. Management authority alone permits management content/analytics but does not make an administrator an audience member or record engagement. Never default an empty/invalid audience to all company users. Agent relinks never transfer assignments, events, authorship, receipts or communication access.

Base lifecycle is draft/published/archived. Creation is draft; explicit publication requires a nonempty selected audience of 1–500 currently eligible confirmed/nonanonymous active tenant Auth users. Preserve fixed Auth identities and retained names; searched bounded selection must cover the whole eligible roster. Published content and assignments can be edited under current authority with revisions. Audience edits revalidate only new additions; preserve unchanged inactive assignments and retained names. Published metadata edits/restore must not drop or reject original assignees solely because they became inactive. Initial publication may require every selected actor currently eligible. Archive/restore is a CT Alt retention extension, preserving the pre-archive state; restoring published resources still enforces current reader eligibility. No deletion or assignment fallback.

Each base has an aggregate revision changed by any management operation; every node has its own revision. A node is folder/text/link, with immutable ID/base/tenant and ordered siblings. Top-level sections are folders; text/links need an active folder. Depth is virtual base root0, section1 and every retained node level ≤16, including archived descendants. Enforce this limit for the entire moved subtree. Reject cycles, self-parenting, cross-tenant/cross-base destinations and inactive ancestors. Move within a base preserves node identity/history. Archive a folder only with no active children; restore only under active ancestors. Archived children and history remain retained. Do not silently cascade. Only restore may newly mutate an archived base; node/audience/content/order edits wait for base restore. Archived node edit/move may retain archived status under an active base and ancestors; restoring must not implicitly restore any descendants. Persistent Move earlier/later and Move to folder controls update ranks/revisions atomically under the aggregate base revision and are keyboard accessible; drag/drop and cross-base moves remain later if absent.

Names 1–100 UTF16 units, descriptions 0–500; text 1–50,000 UTF16 units with exact whitespace/newlines and escaped rendering; link URLs 1–2,000 units parsed as http/https only and intentionally opened externally. A shared conservative URL grammar must agree across UI/API/direct RPC: ASCII DNS labels (1–63 units, host≤253, a letter-bearing final label excluding hexadecimal numeric forms), or canonical decimal IPv4; optional decimal port1–65535. Credentials, IPv6/bracket, Unicode/percent-encoded/punycode authorities are unsupported in this increment. Preserve Unicode paths/query/fragments, rejecting whitespace/control/backslashes and malformed percent escapes consistently. This authority restriction is a documented CT Alt limit, not complete reference URL parity. No HTML execution, SSR URL fetch, link metadata crawler or fake file upload. Enforce two separate bounds: raw app-route JSON transport ≤256KiB (UI/API), and deterministic decoded semantic payload budget ≤256KiB (UI/API/direct RPC). The semantic budget is1024 plus UTF8 bytes of every string value recursively plus64 per object,32 per array and16 per other primitive, using the complete `{tenantId,operationId,change}` envelope. SQL reconstructs that envelope from its UUID arguments and change. Do not cap SQL jsonb::text as though its escaping/spacing equalled browser JSON serialization. UI must check both limits and explain that a max-length text with escaped controls may exceed the transport bound. Reject NUL (U+0000) and unpaired surrogates in UI/API; PostgreSQL text/UTF8/JSONB cannot represent them. Preserve other legal controls/newlines without trimming. Oversize is413; other invalid data fail closed. Direct signed RPC validation must match API null/shape/Unicode limits.

Audience editing is explicit static selected-user mode; new matching employees do not automatically join. Base-level assignment applies to all descendants, matching reference evidence. Folder-specific audiences are not implemented or claimed. Retain existing inactive selected actors/history; new selection validates current eligibility. Future dynamic Smart Group assignment requires a separately reviewed contract, eligible linked Auth resolution and fail-closed invalid-source handling. Current Smart Groups remain organizational records, and existing Chat/Updates identities/permissions stay unchanged.

Reads are side-effect-free coherent STABLE invoker snapshots with bounded default50/max100 paging and literal search ≤100. Catalog management has all lifecycle statuses for recovery; reader catalog only assigned published bases. Folder lists, title search, node readers, assignee picker and insights are distinct current scopes. Fresh signed recheck before release verifies actor/company/role/capabilities, base revision/status/audience and relevant node/path/version. Opaque SQL keysets bind identity, base, path, search/order and relevant definition/population versions; preserve SQL Unicode positions. Failed or changed access returns real 401/403/409/503, never apparent successful emptiness.

Mutations use current authority before payload-bound actor/company operation receipts, expected aggregate/node revisions and a short base/tenant mutex with ordered locks. Same UUID yields one operation/audit/event; changed replay denies. Management receipts may acknowledge a prior authorized write after lifecycle changes without rewriting it. Personal view replay requires current reader/audience/published/active-path authorization before receipt. Public new tables have signed SELECT-only RLS; private receipts default-deny. Explicitly neutralize PUBLIC/anon/authenticated/service-role default EXECUTE and grant only intended authenticated wrappers/helpers. Public RPCs invoker/empty search path, necessary private definers guarded/current tenant-scoped, no raw Auth/contact export. Preserve every applied baseline and existing public/private table/function metadata.

Path DTOs contain ancestors excluding the selected node; a child-list path includes the selected parent, and the base root path is empty. Base insights aggregate every actual base and node open in that base; node insights cover only that exact node, without an implicit descendant rollup. Label the aggregate as resource opens.

Views are explicit successful rendered opens bound to original base/node/content revisions and independently authorized reader mode, separate from GET/list/tree/search/metadata/management reads. View events do not change the management aggregate revision, which would otherwise cause unrelated reader conflicts; insights include a separate evaluated event/audience version. Count one event per deliberately entered base/folder/text/link and one UUID per actual open; retries must not multiply it. A refresh or recovery of the same selected object does not invent another view. Entering a folder need not repeatedly count the already entered base. Management opens record none unless the actor deliberately switches to their independently authorized reader view. Opening a link counts opening its CT Alt resource card, not proof of visiting/reading the external destination. Files/download views remain a separate next contract.

Insights retain original Auth actor IDs/name snapshots, node identity and server timestamps. Report current selected audience, including unavailable assigned records explicitly; percentage denominator is currently eligible assigned accounts and numerator is distinct event actors intersected with that current eligible set. When denominator0, show No eligible audience and percentage unavailable. Per-user totals/last views and the chart cover every current assigned actor, including unavailable ones, clearly labelled Current assigned audience; removed actors remain historical stored events outside those displayed totals. Distinct eligible-view percentage is separately labelled. Keep removed/inactive historic events in storage without transferring them to replacement Agent links. Label current-audience metrics precisely; do not claim reference denominator parity. Per-user repeated totals and last viewed are real event aggregates, and a 30-company-calendar-day chart uses correct timezone/DST boundaries. Lifetime view totals use exact decimal strings if bigint; preserve timestamp microseconds. No notifications/Chat/task creation or view-as-confirmation claim. Whole-scope export is a later separately reviewed increment.

UI uses company/actor/role keys, current returned DTO scopes and abort/controller/epoch/mount fences for catalog/tree/search/reader/assignees/insights. Node/path/base changes cannot release delayed private content. Any current denied/malformed/failed read clears all private content, drafts and analytics and locks changes until current successful recovery. Hold every manual/leaf action synchronously during POST; after decoded ACK check mounted/current before any read. Exact in-memory payload retries only; session storage retains only field-free actor/company/action/operation UUID markers. Unknown management recovery uses unfiltered all-lifecycle management reads under current owner/admin, while personal view recovery must verify the original resource under independently current reader access rather than treating an empty generic library as proof. After departure, the marker contains no resource fields: a dedicated read-only-by-effect reconciliation POST/RPC accepts only tenant/actor-bound operation UUID, acquires the same operation mutex to wait for an in-flight view, checks current confirmed active company identity, and inspects only that actor's receipt. A committed view requires fresh current base/node reader permission before returning field-free recorded status; if revoked, recovery stays locked. An absent receipt may return definitive not-recorded after the mutex, clearing only the marker without replay/count or implying content access. Never return stored payload, body/title or resource IDs from reconciliation. Current management authority remains required before management receipt/recovery. Insights cursors bind current audience/event versions as well as base/node scope. Preserve selection across searched assignee pages, all 1–500 bound and combined payload limits.
