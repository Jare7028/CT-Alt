# Desktop Smart Groups delivery contract

Original CT Alt implementation informed by public Help Center guides6114686,6847572,9532107,7159933,8061578,8061301 and8069531. Full evidence is cached outside Git at /tmp/ct-alt-smart-groups-research.md. Preserve the whole workforce roadmap and existing communication/record permissions. Mobile polish is deferred.

Deliver segments and saved dynamic organizational groups. Current confirmed nonanonymous active company owners/admins manage/read this module. Managers/employees cannot access group catalogs, member previews or mutations. There is no cosmetic administrator selection or new cross-module authority. Granular feature/create/group administration, account-based protected All Users/All Admins, content assignments, profile memberships and Users Save as group remain explicit later increments.

Group identity is the Agent workforce record. Match active records, including unlinked ones; exclude archived records. Expose exact counts records/unlinked/eligible/unavailable, where records equals the other three. Eligibility separately means a current linked active confirmed nonanonymous company account. A suspended/unconfirmed/anonymous linked account remains an organizational profile match but is unavailable for communication. Membership does not grant account access. Relinking an Agent never transfers Chat/Updates/history/receipts. Accounts without Agent profiles are not invented or included in this record population.

Require1–10 AND clauses, each `{field,values}`. Fields are title, team or an existing registered custom text key prefixed `custom:`. Each values array has1–25 distinct nonempty literal strings, each at most500 UTF16 input units; one clause matches any listed value, clauses all must match. Text comparisons are exact and case-sensitive, with no implicit lowercase/trim of profile values or supplied alternatives. Missing/empty profile values never match. Preserve meaningful leading/trailing spaces in alternatives; whitespace-only alternatives are invalid. No regex, arbitrary paths, global OR/nesting, zero-rule broadcast or reuse of directory client filters. Relative/absolute dates, typed dropdown identities, numbers and other fields remain later increments.

Never drop invalid fields/rules. New save/preview rejects unknown fields. A retained group with a removed custom field returns explicit needs-review/invalidFields and null population counts, cannot preview/restore until repaired, and can be edited with valid rules. Existing field key is currently identity; future editable/deletable typed fields need stable IDs before reuse. Field labels/order may change without changing a matching key's meaning.

Segments have name/description/status/revision; groups have those plus segmentId and rules. Names1–100, descriptions0–500 input units. Create/rename/edit/move, archive and restore are audited UUID/revision operations. Archive/restore are explicit CT Alt retention extensions; reference documents deletion. Block segment archive while it contains active groups; no cascade, delete or audience fallback. A group needs an active parent to create/edit/restore; archived groups can be repaired while their segment is active. Group archive is allowed even for invalid rules. Preserve rows/history. Current owner/admin authority is checked before prior operation receipt lookup. Payload-bound private receipts use exact actor/company UUID, and acknowledge prior writes without repeating them even after later lifecycle changes.

Use a tenant mutex for short mutations, current identity/company/member locks, current parent/group rows and field validation. Same UUID concurrency yields one write/audit; stale revisions409. Explicitly revoke default PUBLIC/anon/authenticated/service_role EXECUTE then grant only intended authenticated functions. New public tables signed SELECT-only RLS, no direct browser writes; private receipts default-deny. No baseline SQL/permissions/data/Auth changes or app privileged credential. Integrator alone applies hosted additive SQL/releases.

APIs: GET `/api/smart-groups` paged group search/status/optional segmentId; GET `/api/smart-groups/segments` paged searchable segment management/picker; GET `/api/smart-groups/[id]/members` saved rules + exact population and name-filtered paged members; POST `/api/smart-groups/preview` side-effect-free rules preview + matching counts/members; POST `/api/smart-groups` strict `{tenantId,operationId,change}`. All reads require signed owner/admin. Bounded50default/max100 lists, literal search≤100, exact full-population counts beyond1000, no silent truncation. Preview body and mutation ≤40KiB, same origin, valid JSON; combined payload limit must be enforced in UI too. Errors private/no-store JSON400/401/403/409/413/503, never apparent successful empty data.

One STABLE signed invoker snapshot per read includes definition/fields/role/counts/page. Public invoker wrappers use empty search path. Any necessary private Auth eligibility helper exposes only company-bound eligibility and enforces current owner/admin, never contact/Auth details. Fresh signed access check before returning verifies current actor/role/company, returned group and segment revision/status and field fingerprint. Exact keysets bind tenant/actor/role/read kind/group/definition/filter/search plus field and evaluated-population versions; member population changes invalidate pagination409. Preserve SQL name sort positions without JavaScript case recomputation and microseconds/bigint text as applicable. Reads/preview never audit, save or mark any content viewed. Re-evaluate membership on fresh reads; no Realtime claim.

Frontend uses current company/actor/role keys, exact returned DTO scope and abort/controller/generation fences on all leaf reads. Rule changes cancel old previews; show current matching count only for current rules. Picker search/pages preserve selected segment identity. Current failed/malformed/private-access reads clear all group/member/preview/draft data and lock changes until fresh successful scoped recovery. Hold POST synchronously against all manual/leaf reads and changes. After decoded acknowledgement check still mounted/current before any read. Persist only field-free actor/company marker(action/operation UUID), exact in-memory payload retry; departure must not replay fields. Unknown management recovery reads all lifecycle states for the relevant groups/segments under current owner/admin rather than interpreting a filtered empty list as lost permission success.
