## Filters, dates and bounds

All report scopes carry {from:string|null,to:string|null,review:'all'|'reviewed'|'not_reviewed',search:string,submission:'all'|'submitted'|'not_submitted',fieldId:string|null,fieldAnswer:'all'|'answered'|'empty'}. Dates are either both null (all time), or both valid strict YYYY-MM-DD with from<=to and inclusive duration<=366 company calendar days. Filter immutable first submittedAt using PostgreSQL civil dates in company time_zone, including DST; review updatedAt and content lastEditedAt never redefine submission time. Reject malformed/impossible dates, one-sided ranges and unknown/duplicate query keys at API and SQL. Literal case-insensitive retained respondent name search<=100 UTF16/512UTF8, including %, _ and backslash as ordinary characters. Search/review/date filters apply to submitted scope; status search uses retained assignment name and review only to matching submitted row; filtered-out submissions show not submitted in the selected report scope. UI explicitly says 'Submitted in selected period' for a date range and explains when review filters further narrow the scope. submission filter is only valid for status; fieldId/fieldAnswer only for field responses; reject nonsensical combinations rather than ignore them. Canonical unused values: submission=all except status; fieldId=null and fieldAnswer=all except field. Field kind requires a fieldId matching an answerable frozen-schema field; reject absent/description/unknown field IDs. Summary rejects paging cursor (limit may be omitted or default50 only).

Page size1..100, default50. Entries and field rows sort first submittedAt DESC then response UUID DESC; status rows sort lower(retained assignment name) then original actor UUID ASC. Exact total/reviewed/notReviewed entries counts; status counts {total,submitted,notSubmitted,eligible} for the complete filtered status scope, with assignmentTotal/assignmentEligible independent of ALL report filters, including dates/review/search/submission. Status response is null when its submission fails the selected date/review scope, with no out-of-scope ID, timing, review or editor metadata. Summary, field responses and entry export validate their complete selected submitted scope: <=10,000 rows, raw answer bytes<=2MiB, and count times PostgreSQL serialized frozen-schema bytes<=64MiB before complete validation/aggregation. The schema-work limit bounds repeated retained-schema comparison so unusually large schemas cannot make reports time out on Free signed requests. Refuse oversized complete scopes with413 and prompt narrower date/name filters; never truncate. Entry export has those same complete-scope bounds; status export<=500 assignments. Bound RPC JSON and complete XLSX output to8MiB, before returning. Smaller visible pages never constrain complete export. Bounds apply before expensive aggregation/file construction; serialized output checked as well. Preserve genuine empty arrays/zero totals; malformed source/snapshot answers/schema produce503, not invented empty results.

## Summaries, field responses and exports

Shared frozen form schema is returned once, in original ordered fields. Validate each submitted answer against its retained schema, which must equal the frozen schema for this immutable-schema increment; preserve original form title per submission. Description fields are informational and omitted from question statistics/export answer columns. For each answerable field, total=selected submitted count, answered+empty=total. Missing/blank-or-whitespace optional text and empty optional multiple-choice arrays count empty. Boolean false counts answered; valid submitted decimal strings count answered without conversion. Single-choice option counts and yes/no counts sum to answered; multiple-choice option counts may total more than answered. Choice distributions use retained stable option labels and denominator answered respondents, visibly identified; percentages display one decimal place using Math.round(1000*count/answered)/10, and when answered=0 display No responses without a percentage; count and percentages must not conflate selections with respondents. All field counts safe exact integers. No approximate/sampled summaries. Field response page contains original response summary plus only that field's answer or null and explicit answered flag; link to existing response detail, no private progress/history.

Genuine .xlsx only: dependency-free bounded ZIP STORE + CRC32/central directory with original OOXML, fixed sheet names. Entries workbook contains Report metadata and Submissions sheets; status workbook Report and Assigned users sheets. Metadata gives company, current form name, exact filters/timezone, exportedAt UTC and totals. Suggested entry columns: response ID, original actor ID, respondent, original form title, first submission UTC, content editor ID/name/UTC, reviewed flag, reviewer ID/name/UTC, then ordered answerable question labels. Status columns: actor ID, retained assignment name, current eligible flag, submitted in selected scope flag, response ID, first submission UTC, review flag and content editor name/UTC. Missing values are empty text cells; retain exact textual values. Yes/no human labels Yes/No; choices map stable UUID to retained label; multi-choice labels use JSON array text to avoid delimiter ambiguity. Decimal answers and six-digit UTC timestamps are text to preserve precision. Count cells may be numeric safe integers. All user content inlineStr, no formulas/macros/external links or external relationships. Required internal package/workbook/worksheet relationships are permitted. Preserve =,+,-,@ text without modifying it. XML escape plus correct SpreadsheetML literal _xHHHH_ escaping/forbidden control and CR encoding; no dropped Unicode/whitespace. Strict full output size bound; Content-Type application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, private no-store, nosniff, attachment safe fixed ASCII filename and actor/company/form/version headers. No public URLs or stored export files.

The export route must deliver already fully validated complete bytes through a pull-based ReadableStream in bounded chunks, after the final signed access/version recheck. A buffered5–8MiB response would exceed Vercel's4.5MB response limit. Streaming is transport only, never a partial scope or deferred verification: validate the complete workbook first; no bytes leave before access is rechecked. Cancel releases the stream's bytes; no persistent export artifact.
