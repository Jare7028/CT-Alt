# Team timesheet review and CSV export

Original CT Alt desktop implementation informed by the official [Timesheets Tab guide](https://help.connecteam.com/en/articles/9420509-the-time-clock-s-timesheet-tab) (8 September 2026) and [Time Clock Export Options](https://help.connecteam.com/en/articles/5917303-time-clock-export-options) (25 August 2026). Those guides describe administrator date-range reviews, user summaries and whole-team or individual-user exports. This slice provides recorded time review and CSV; payroll formats, rates, overtime, timesheet editing, issues, approvals, absence data and full feature/pixel parity remain incomplete. No competitor assets or private workforce records were imported.

## Data and authorization

Owners/admins can review all completed entries for an explicit company and inclusive company-calendar start/end dates. Dates select the shift's **start**, including overnight entries, rather than calendar overlap. The optional user filter uses the retained agent ID. Archived agents, suspended memberships and archived jobs keep their recorded entry names and time history; the actor still needs current confirmed, nonanonymous, active owner/admin membership in an active company. Managers/employees and foreign, suspended or unconfirmed actors cannot review/export team records.

One STABLE SECURITY INVOKER RPC, `read_team_timesheets`, uses existing RLS and the existing clock day-boundary and entry-total helpers, with an empty search path. Execute is authenticated-only; PUBLIC/anon/service-role grants are explicitly revoked. No privileged application credential or new definer is introduced. The app checks signed current company/role/timezone before and after the read. Returned identities, filters, counts, durations, completed records and cursor scope are validated; errors do not become apparent empty summaries.

The reviewed additive SQL is recorded as `20261003225247_team_timesheets.sql`; its previously unapplied CLI filename was matched to the server-assigned version after application without changing SQL. Applied `20261003215840_time_clock_baseline.sql` stays immutable. Its narrow policy change replaces the existing per-row `auth.uid()` comparison with `(select auth.uid())`, preserving the same current identity/member/active-agent authorization and addressing that policy's Auth initplan performance advisory. Existing table grants and function definitions, owners, ACLs and security settings are preserved.

A partial `(tenant_id,id desc)` clock-out audit index supports the completion-version lookup without removing existing indexes.

## Snapshot, paging and export

The selected-range summary contains exact completed entry/user counts and elapsed, unpaid-break and tracked-time totals, independent of the current page. Summary, page, retained user choices and dataset version share the RPC's statement snapshot. Pages use descending `(started_at,id)` keysets and preserve microseconds. Cursor scope binds company, actor, dates, user, timezone and the latest committed tenant clock-out audit ID as **bigint text**. Baseline completed entries are immutable and mutations serialize through the tenant mutex. A later completion invalidates an older cursor with409, even if it falls outside the selected range; refresh starts a new review. Future edits/deletes must also advance or replace this version contract.

`GET /api/team-timesheets?tenantId=...&startDate=...&endDate=...` returns review JSON. Optional `agentId`, `limit` (1–100) and `cursor` narrow/page it. `mode=export` accepts no cursor/limit and returns a UTF-8 CSV containing **all** selected completed entries from one bounded snapshot, independently of displayed pages. More than10,000 matches raises413 and produces no partial download. Current authorization/role/timezone is checked again before the response. The client requests this complete export directly; it never assembles CSV from accumulated pages. A successful export may include newly completed records since the displayed review, and always applies the displayed review's date/user filters.

Team entries retain the existing clock identity/name/time/revision/totals fields and omit individual break arrays to bound payload size. CSV includes retained user name/ID, job name, original precise clock-in/out timestamps, company timezone, elapsed seconds, unpaid-break seconds and tracked seconds. It uses the directory's `csvCell` utility for formula/control-prefix neutralization and quote/newline escaping. CSV is recorded time data, without pay calculations.
