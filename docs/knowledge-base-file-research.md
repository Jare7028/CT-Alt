## Verified provider documentation

- [Bucket fundamentals](https://supabase.com/docs/guides/storage/buckets/fundamentals): private-bucket uploads and downloads are governed by storage.objects RLS. Authenticated downloads use the signed user's JWT; public bucket reads bypass access control.
- [Storage access control](https://supabase.com/docs/guides/storage/security/access-control): upload requires INSERT; upsert additionally needs SELECT/UPDATE. Default storage access denies uploads. Operation-aware helpers distinguish authenticated object retrieval from listing. A service key bypasses RLS and must not become an application credential.
- [File limits](https://supabase.com/docs/guides/storage/uploads/file-limits): Free project's global file-size setting cannot exceed 50 MB. Per-bucket caps must not exceed the global cap. A subsequent read-only CT Alt inspection confirmed the global limit is52,428,800 bytes (50 MiB), no buckets, zero recorded storage objects and zero recorded object bytes. Installed storage.allow_only_operation/allow_any_operation helpers are available. Physical orphan bytes and remaining egress were not verified; do not claim full free capacity.
- [Standard uploads](https://supabase.com/docs/guides/storage/uploads/standard-uploads): multipart uploads support small files; Supabase recommends resumable TUS above 6 MB. This is separate from the application host's request limits.
- [Private downloads and signed URLs](https://supabase.com/docs/guides/storage/serving/downloads): signed URLs use a separate internal key, remain valid until expiry and are unaffected by Auth signing-key rotation/revocation. Do not claim a previously issued URL is revoked immediately when audience membership changes.
- [Current Free pricing](https://supabase.com/pricing): advertised 1 GB file storage, 5 GB egress and 5 GB cached egress. Included limits do not establish remaining account usage or authorise billing. Verify actual CT Alt usage before choosing a smaller supported product quota.
