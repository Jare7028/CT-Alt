# Single-shift Templates desktop increment

This original CT Alt drawer follows the publicly documented scheduling workflow. The official reference is [Schedule Templates](https://help.connecteam.com/en/articles/3524929-schedule-templates), updated 17 August 2026, and [Creating Shifts](https://help.connecteam.com/en/articles/8986051-creating-shifts), updated 16 July 2026. Public images establish a right-side panel, template cards, search and Add Template; they do not establish current authenticated geometry, free-plan entitlement or complete product parity. CT Alt retains its own branding, application shell, code and artwork. No vendor screenshots or private reference content are committed.

Managers can search and page actual schedule-scoped templates; add, edit, duplicate and delete recipes; capture the persisted contents of a draft or view a published shift without editing it; and apply a recipe to a current active roster worker on a chosen date. Application creates one private draft. The existing Publish action still publishes all schedule drafts. Recipes follow the schedule's current time zone. Preview rejects clock gaps, requires an occurrence for folds and shows actual UTC instants and elapsed duration. Source UTC seconds, any nonzero fractional-second digits (including PostgreSQL microseconds beyond JavaScript Date precision), or local wall seconds from historical second-based time-zone offsets require explicit minute normalization; original shift instants remain unchanged. Archived schedules expose a read-only list. Employees have no entry; server and SQL authorization remain authoritative.

An operation UUID and immutable payload stay in memory while saving. Before sending, browser storage records only the tenant/actor-scoped operation identity, action, schedule and target template, without recipes, worker identities, names or contact fields. Lost acknowledgements lock mutation and close controls. Reload or navigation preserves that marker and reopens the status check. Only a verified recorded or authoritative not-recorded reconciliation resolves it. Failed recovery keeps the lock. Current permission rejection clears visible scheduling data and invalidates older responses, while retaining the identity marker for a later authorized status check. Browser storage failure prevents sending a mutation. Markers are recovery hints rather than authorization tokens.

The synthetic component runner is `node scripts/test-rota-templates-ui-browser.mjs`. It creates one disposable local route, probes exclusive port 5198, disables hosted configuration, verifies page/overlay/interactive content with a named agent-browser session, runs Playwright and removes only its own route/server. All operational responses are synthetic intercepted APIs; this does not establish genuine signed Auth, SQL behavior or production acceptance. Original rendered desktop captures are inspected outside Git at `/workspace/scratch/ct-alt-shift-templates-original.png`.

The browser cases cover CRUD, one draft application and retained draft on template deletion; lost acknowledgement with failed then recorded recovery; not-recorded recovery; current permission denial; published source and explicit precision normalization, including UTC minute-aligned instants with historical local wall seconds, nonzero microseconds and an all-zero fractional precision control; reload/departure marker privacy and recovery; held acknowledgement locks; late list after revocation; IANA gap and both fold occurrences; archived read-only controls; pagination revision fences; keyboard close/focus restoration; and a manager’s revoked-but-readable schedule marker retained without blocking a different delegated schedule’s reload or job mutation. Restoration only selects currently manageable returned schedules, using current role and delegation, and clears transient locks for inaccessible drawer scopes. Integrator owns whole checks, genuine Auth/SQL evidence, independent review and release.

Day/week templates, drag/drop, assignment preservation, recurrence, open shifts, capacity/claim approvals and scheduler Requests are separate increments. This drawer exposes only supported Shifts controls and does not present placeholder tabs or simulated notifications.
