# Knowledge Base desktop baseline acceptance

This is an original bounded implementation of the [reviewed contract](KNOWLEDGE_BASE_CONTRACT.md), grounded in the [public reference research](knowledge-base-reference.md). It supports multiple fixed Auth-audience bases, folders to depth16, exact plain text and external links, hierarchy moves and sibling ordering, title search, explicit reader views and current-audience insights. It does not claim complete Connecteam parity.

## Identity, permissions and retained history

Current confirmed, nonanonymous active company membership is checked on every signed request. Owner/admin management access is separate from personal engagement: even administrators require a current assignment to open the published reader and record a view. Audience identities are original Auth UUIDs, independent of Agent-record linkage. Relinking an Agent never transfers content access or view history. Drafts allow0–500 assignees; publishing requires1–500 currently eligible assignees. Published edits retain unchanged inactive assignments and names; only additions require eligibility. All descendants inherit the base audience.

Management changes use aggregate base and targeted node revisions, a short tenant mutex, audited writes and actor/payload-bound UUID receipts. Views use the same actor/operation mutex as field-free reconciliation, record precise server timestamps and do not increment management revisions. Exact recorded view retries still acknowledge their original event after unrelated edits, while fresh stale rendered-view commands fail409. Current assignment, published state and active ancestor path are checked before any personal receipt replay. Recorded view reconciliation uses two resource-guarded signed RPC calls; its five-field response never exposes stored base/node IDs or content. An absent receipt is definitive only after waiting behind an in-flight operation. Access can still change after the final database check; the client fences scoped responses and handles the next denial.

New tables expose signed SELECT only; events/audit are management-only. Public RPCs are invokers with empty search_path and authenticated-only EXECUTE. Explicit revocation covers PUBLIC, anon, authenticated and service_role before intended grants, including permissive hosted function defaults. Private definers have explicit gates/ACLs; application code uses no privileged key. GET/list/search/insights/recovery never record views. Only a deliberately rendered reader entry sends the explicit view command.

## Exact data and pagination

Names, descriptions, bodies and link inputs preserve legal whitespace; names must be nonblank. Bounds use UTF16 units:100/500/50,000/2,000 respectively. NUL and unpaired surrogates are rejected. Requests have separate262,144-byte raw JSON transport and deterministic semantic budgets (1024 plus UTF8 string bytes,64/object,32/array,16/other primitive). SQL validates the reconstructed semantic envelope rather than jsonb::text escaping.

Links use a shared conservative grammar: http/https, ASCII DNS authority (labels1–63, total≤253, final label contains letters but is not hexadecimal-number shaped) or canonical decimal IPv4, optional port1–65535. Credentials, IPv6/bracket authorities, Unicode/percent-encoded authorities and xn-- IDN labels are outside this baseline. Tails retain Unicode and legal percent escapes; whitespace, controls, backslashes and malformed escapes are rejected. API also parses the accepted URL. Links are not fetched server-side.

Exact statement counts, bounded100-row pages, literal title search and scoped opaque SQL sort positions support more than1,000 records without a directory cap or JavaScript Unicode case-fold reconstruction. Cursors bind actor/company/view/query/resource revisions, audience/tree/roster/event versions and company calendar. Fresh signed access checks reject changed authority403 or changed readable resource/version409, and failed reads return an error rather than fabricated zeros. Ranks/view counts remain precise bigint strings. Paths exclude the selected node and include the selected parent in child lists.

Insights include current assignments, unavailable retained assignments, eligible-viewer denominator, precise latest timestamps, exact lifetime opens and a30-company-calendar-date chart. Base insights aggregate all actual base/node entries; selected-node insights count that node alone. Events belonging to removed assignees stay stored but are excluded from current-audience metrics. Zero eligible users yields a null percentage. Calendar bucketing uses each event's actual company-local date, including repeated midnight,23/25-hour dates and skipped dates.

## Fresh-statistics large-tenant performance

The path helper remains STABLE, SECURITY INVOKER, empty search_path with the same ACL. It walks at most16 ancestors through exact tenant/base/primary-key lookups; each actual ancestor still passes signed RLS. Null/missing/inaccessible paths return empty; cyclic or excessive paths fail closed. A fresh-statistics fixture adds1,005 Auth users/members and1,005 depth3 text siblings, checks the exact1001-match100-row search and root-first paths, and bounds current-transaction membership-role calls rather than hardware-dependent elapsed time. The disposable runner disables autovacuum only to keep this fixture's statistics deterministically fresh.

A separate offline benchmark with1,005 Auth members and1,005 nodes measured a single100-row signed search at8.973s before the bounded walk and1.102s after (about8×), with membership-role calls205,130→3,830. Analyzed-table timings were0.863s before and0.876s after. The recursive join previously chose unrelated full-node scans under fresh statistics, multiplying RLS checks; bounded primary-key reads remove that dependency without bypassing or caching authorization. These sampled times are diagnostic evidence, not a production latency guarantee. All applied baselines remain unchanged.

The boolean active-path gate separately remains STABLE, SECURITY DEFINER, empty search_path with unchanged ACL. It first checks current confirmed active company membership and the existing owner/admin-or-published-assigned-reader rule, then walks only scoped tenant/base ancestors. Each ancestor must exist and remain active; missing, cyclic or more-than16-node chains return false. Authorized null paths retain their original meaning. No role or authority is cached across calls, and no foundation function or policy changes.

With the same fresh1,005-Auth/1,005-node fixture, an assigned employee's node RPC plus fresh access check measured3.487s before and1.136s after this second bounded walk; analyzed totals3.145s→0.970s. Exact signed actor, body and root-first path stayed unchanged. The deterministic regression bounds combined current-role calls≤6,500 instead of asserting elapsed time, and tests membership suspension, unconfirmed Auth, audience removal, archived ancestors, missing ancestors, cycles and exact depth16 versus17. These offline samples exclude actual Auth/network/rendering time and are not a production guarantee.
